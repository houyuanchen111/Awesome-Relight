# Contributing

Thanks for helping keep **Awesome Relight** useful and current.

## What to Add

We welcome resources related to relighting, illumination editing, inverse rendering for relighting, light estimation, relightable 3D assets, relightable avatars, video relighting, datasets, benchmarks, workshops, demos, and practical tools.

Good additions usually include:

- Paper title, venue, and year
- Paper, project, code, demo, dataset, or benchmark links
- A short category placement that matches the current README
- Public code links when available

## Entry Format

Use the existing compact badge style:

```md
- **Method Name**, "Full Paper Title". [![arXiv](https://img.shields.io/badge/arXiv-0000.00000-b31b1b.svg)](https://arxiv.org/abs/0000.00000) [![Website](https://img.shields.io/badge/Website-Link-blue)](https://example.com) [![Code](https://img.shields.io/badge/Code-GitHub-green)](https://github.com/user/repo)
```

If a paper has no short method name, use the title in bold.

## Organization Rules

- Put papers in the most specific section first.
- Prefer chronological order inside a subsection, with newer work near the top when the subsection is trend-focused.
- Do not add duplicate entries unless a work naturally belongs in both a paper section and a dataset/software section.
- Keep descriptions factual and concise.
- Use official project, paper, and code links when possible.

## Pull Requests

Before opening a PR:

- Check whether the resource is already listed.
- Confirm that links resolve.
- Keep formatting consistent with surrounding entries.
- Explain why the resource belongs in the repository when the placement is not obvious.

For larger taxonomy changes, open an issue or PR with a short rationale.
